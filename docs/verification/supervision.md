### Attended posture

On 2026-11-08, an isolated Linux fixture using Bash 5.2.15 and Node 22.23.4 exercised the real watcher, host, grants, outcome owner, drain and Stop hook with a supplied engine judgment and a stand-in primary.
The same routine check produced one primary wake and no engine turn before host triage, then no primary wake and one engine turn afterward.
`tests/fm-supervision-host-hook.test.sh` covers batched check observations (including an unknown observation name), signals and stale rows remaining on the host, while decisions, real blockers, dead presented listeners, stuck workers and pending requested results reach MAIN.
Those failure judgments are fixture inputs; the test proves routing and durable delivery, not a model's diagnosis of a live failure.
An additional empty-queue recovery case proves that saved captain outcomes still wake MAIN and remain presented until processed.

The interrupted-turn cases in `tests/fm-supervision-host.test.sh` pin an already-announced successor close before TERM or SIGKILL.
Both forced runs recovered the queued return result after restart, using the existing turn checkpoint and recovery-marker owner.
An abandoned empty turn remained a no-op with no engine or MAIN turn.

The relay signal fixture in `tests/fm-claude-stop-autoarm.test.sh` terminates a foreground hook after arming and queuing an observation.
Without matching handoff intent it retains the ordinary interrupted failure and exit 2; matching current-client stowing, opening or stow-ready intent instead closes cleanly and preserves the queue.
Foreign-session and wrong-nonce cases retain failure delivery.
This is a hook protocol test, not a native client's `/exit` test or proof of a historical exit failure's cause.
No real client session or external relay controller was driven, and macOS was not exercised.
